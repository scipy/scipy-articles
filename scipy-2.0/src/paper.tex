\section{A New Look at Language Choices}

As discussed in~\cite{Virtanen2020}, much of SciPy's original success can be attributed
to the convenient Python interfaces it provided to popular compiled numerical libraries
that were otherwise distributed primarily as standalone Fortran source
packages, such as those available through the Netlib repository~\cite{netlib}.
These included
ODEPACK~\cite{Hindmarsh1983ODEPACK},
VODE/ZVODE~\cite{Brown1989}, and DOPRI5~\cite{Hairer1987} for solving initial value
problems; QUADPACK~\cite{Piessens1983} for quadrature; FITPACK~\cite{dierckx1995curve}
for spline fitting; ID~\cite{martinsson2008id,Halko2011} for interpolative
matrix decomposition; ODRPACK~\cite{Boggs1989}
for orthogonal distance regression; COBYLA~\cite{Powell1994}, L-BFGS-B~\cite{Morales2011},
SLSQP~\cite{Kraft1994,Kraft1988SQP}, MINPACK~\cite{More1980}, and
NNLS~\cite{Lawson1995} for optimization;
ARPACK-NG~\cite{Lehoucq2023ARPACKNG} and PROPACK~\cite{Larsen1998} for sparse eigenvalue problems
and singular value decompositions, respectively; AMOS~\cite{Amos1986} and
SPECFUN~\cite{Zhang1996} for special functions;
CDFLIB~\cite{Brown1994CDFLIB}, mvndist~\cite{Genz1992}, and
statlib~\cite{Dinneen1976,Best1975,Royston1995,Maclaren1985} for probability
distributions and statistical functions;
and FFTPACK~\cite{Swarztrauber1982} for fast Fourier transforms.
Consequently, SciPy 1.0 consisted of approximately $50\%$ Python, $25\%$ Fortran,
$20\%$ C, $3\%$ Cython, and $2\%$ C++ code~\cite{Virtanen2020}.

Despite the enormous utility these codes have provided, they also presented a number
of challenges on the road to SciPy 2.0. By far the most significant of these was
limited availability of Fortran compilers for Windows and
emerging new platforms such as WebAssembly~\cite{Haas2017}. This left SciPy
in a precarious position where distributing SciPy was challenging and required
a custom MinGW toolchain to build SciPy on Windows~\cite{obermeier2023eu}.
While tools such as \texttt{flang-new} (now \texttt{flang})
and \texttt{LFortran} showed promise in addressing this issue, they were not
mature enough to be adopted by SciPy at the time and waiting for them to mature was
deemed not viable.

In addition, there were a number of further issues pertaining to the Fortran 77
implementations of these codes. A number of them were not thread-safe,
meaning that they could not be safely called from multiple threads simultaneously.
Previously, SciPy used locking to prevent this. However, the introduction of
free-threading in CPython 3.13, and its subsequent maturation in CPython 3.14, meant
that, for the first time, multiple threads could execute Python code concurrently
without the Global Interpreter Lock (GIL)~\cite{gross2023pep703}. Unfortunately,
users of these non-reentrant codes would not be able to take advantage of this
new feature.
Other challenges presented by these codes included a lack of support for
64-bit integer types (ILP64) and lack of control over the random number generator used.
Finally, many of these codes were no longer actively maintained, meaning that the
SciPy developers were effectively responsible for fixing any bugs that arose.
This increased the maintenance burden and made it more difficult to resolve bugs and
improve these routines. This was further compounded by a lack of expertise in Fortran
77 within the SciPy developer community, which often led to bugs remaining unresolved
indefinitely.

After careful evaluation of the above issues, it was decided that these
codes needed either to be replaced with
more recent, actively maintained alternatives, or to be translated from their
original Fortran 77 source code to either pure Python,
Cython~\cite{Behnel2011}, or C/C++ in order to secure the long-term future of the
project. Consequently, COBYLA has been replaced with
a Python implementation from the PRIMA~\cite{Zhang_2023} package, FFTPACK has been replaced with
ducc.\@fft~\cite{reinecke2019ducc}, and some of the special and statistical functions
mentioned have been replaced with counterparts from Boost.\@Math~\cite{boostmath}. Translation of the remaining
codes posed a significant undertaking, requiring a significant proportion of SciPy's
$\sim80{,}000$ source lines of Fortran 77 to be translated by hand. The completion of this work has been a major milestone for
SciPy 2.0, leading to the resolution of the challenges described above as well as many
long-standing bugs. Furthermore, these translations provide the foundation for
future development and improvements, for example, improved special functions, as
discussed below.

\section{When Random is not Good Enough: New Functional for Quasi-Monte Methods}

Both NumPy~\cite{Harris2020} and SciPy provide functionality for generating
(pseudo)random numbers following a multitude of different distributions. These
random number generators
often form the basis of Monte Carlo (MC) methods, which are frequently applied to tackle
fundamental tasks such as sampling, estimation, and optimization~\cite{Kroese2014}.
Monte Carlo methods are especially useful when the dimensionality of the problem is
high meaning deterministic methods are infeasible.

A prototypical example of this is integration over the unit hypercube,
which is infeasible when computed by taking the tensor product of standard, one
dimensional quadrature rules or even specialist cubature rules if the
dimensionality is large. The Monte Carlo method estimates the integral by evaluating the
integrand at points that are independent and identically distributed (IID) uniform random
samples~\cite{Hammersley1960}. It is well known that, provided the intergrand is square integrable,
then this approach has a probabilistic error bound of the form $O(n^{-1/2})$, where $n$
is the number of points the intergrand is sampled at. While this
convergence rate has the important property of being independent of the dimension $s$,
it is still rather slow. This led to the development of Quasi-Monte Carlo (QMC) methods,
for which the sample points are chosen deterministically from a
\emph{low-discrepancy sequence} to achieve a faster convergence rate.
This is achieved by choosing points that are more evenly distributed than random points,
avoiding clustering and large gaps that are typical of random points.
For a more detailed discussion and introduction of QMC methods, we refer the reader
to~\cite{Niederreiter1992,Dick2010,Dick2013,Giles2008}. While QMC methods have many
advantages, they generally require more care in their implementation and use than MC
methods~\cite{Art2020}.

\begin{figure}
    \centering
    \includegraphics{figures/qmc.pdf}
    \caption{Examples of samples generated from MC and QMC methods and their
    associated centred discrepancy. For panels (A)-(D) we generate $n=128$ points in
    $[0,1]^2$ using (A) IID uniform random sampling, (B) Sobol'
    sequence, (C) Halton sequence, and (D) Latin hypercube sampling.
    Panel (E) is generated using Poisson disk sampling to fill the space with point
    that have a minimum distance of $0.01$ between them.}
    \label{fig:qmc}
\end{figure}

SciPy 2.0 contains a new submodule, \texttt{scipy.stats.qmc}, which provides
convenient and accessible building blocks for implementing QMC methods~\cite{Roy2023}
that are carefully implemented to avoid the common pitfalls, such as those
discussed in~\cite{Art2020}. It implements Sobol'~\cite{Sobol1967,Joe2008} and
Halton~\cite{Halton1960,Halton1964} low-discrepancy sequences as well as
Latin hypercube~\cite{McKay1979,Iman1981} and Poisson disk~\cite{Cook1986,Bridson2007}
sampling methods, which are some of the most widely used QMC methods. Samples generated
from these methods are illustrated in Figure~\ref{fig:qmc}. These samples can also
easily be scrambled in order to give improved convergence rates and allow for practical
error estimation~\cite{Owen1998,Owen2003}, similar to those that are obtained for Monte
Carlo methods. Functionality is also provided for measuring the uniformity, known as the
\emph{discrepancy}, of a set of points, which is used to quantify how well the sample
points cover the sampling space~\cite{Zhou2013,Warnock1972,Warnock1995}.
It is possible to reduce the discrepancy of a sequence using one of the inbuilt
optimization methods, based on either random permutation or Lloyd
iteration~\cite{Lloyd1982}.

Not only does this new submodule provide users the required tools to implement
QMC methods, it also provides the foundation for other functionality within SciPy.
For example, returning to the motivating example above, \texttt{scipy.integrate} now
contains new functionality for quadrature using QMC methods.
Elsewhere, SciPy's differential evolution~\cite{Storn1997} and
simplicial homology~\cite{Endres2018} global optimization algorithms now utilise SciPy's
new QMC functionality to generate their initial populations, providing better coverage
of the search space than the IID uniform random sampling. This space filling property
also makes QMC methods the perfect candidate for generating sample points when
interpolating high-dimensional functions using methods such as radial basis functions
and nearest-neighbour interpolation implemented in \texttt{scipy.interpolate}.

QMC methods are also used extensively in SciPy for sampling from distributions.
Within the \texttt{scipy.stats.qmc} submodule, functionality is provided for generating
samples from the multinomial and multivariate normal distributions using QMC methods.

Another new feature in SciPy 2.0 that utilizes QMC methods, is the new functionality
in \texttt{scipy.stats} for global sensitivity analysis (GSA) using Sobol'
indices~\cite{Sobol1993,Sobol2001}. This function helps users to determine how much
of the variance in the output of their model can be attributed to each of the input
parameters and uses QMC methods to generate the function samples required to compute the
Sobol' indices. This addition helps to improve the accessibility of GSA methods, while
leaving more specialized methods to other libraries such as SALib~\cite{Herman2017}
